# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Hearts of Iron IV companion web app for planning campaigns, starting with a national focus tree planner (production, divisions, navy, etc. may come later). It is a client-side Vue 3 + TypeScript + Vite single-page app with no backend.

## Commands

- `npm run dev`: start the Vite dev server (the app is served under `/hoi4-companion/`)
- `npm run build`: run `vue-tsc` type-check and `vite build` in parallel, writing to `dist/`
- `npm run test`: run Vitest once (`npx vitest run src/domain/__tests__/focusPlan.test.ts -t "name"` for a single file or test)
- `npm run type-check`: type-check only (`vue-tsc --build`)
- `npm run lint`: ESLint with `--fix` (flat config in `eslint.config.ts`)
- `npm run format`: Prettier on `src/` (no semicolons, single quotes, print width 100)

Tests live in `__tests__/` folders, which `tsconfig.app.json` excludes from type-checking.

## Deployment

Every push triggers `.github/workflows/main.yml`, which runs `npm install` and `npm run build`. Pushes to `main` also deploy `dist/` to GitHub Pages. That is why `vite.config.ts` sets `base: '/hoi4-companion/'`. Keep that base path when changing routing or asset URLs.

## Architecture

**No game data is committed or hosted.** The app reads focus trees from the user's own Hearts of Iron IV install, in their browser, and caches the parsed result in IndexedDB. Never add extracted game files or data to the repo. `HOI4_DIR="/path/to/Hearts of Iron IV" npm run test` also runs a test against a real install (skipped otherwise).

- Game logic is plain TypeScript with no Vue or DOM imports, so it is testable in Node. Keep it in `src/domain/`. Components only render it. Its subfolders are the architecture: `plan/` is the planner (it depends on nothing but `focus.ts`, and knows nothing about game files), `campaign/` is the whole picture built from the plans (`countryStateAt` in `campaign/countryState.ts`: the active ideas, stat totals, popularity, ruling party and leader of the country at a date; future planners add their inputs here), `parsers/` reads game script, `effects/` turns a focus's reward into display lines, and the files left at the top (`focus.ts`, `stats.ts`, `gameFiles.ts`, `gameImport.ts`, `definitions.ts`, `names.ts`, `focusEffects.ts`) are the shared types and the importer that drives the rest. Tests for all of it stay in `src/domain/__tests__/`.
- Import pipeline:
  - `parsers/paradoxScript.ts` is a generic parser for Paradox script. It keeps duplicate keys and order. The other files in `parsers/` each read one kind of definition out of it, and are used only by `gameImport.ts`.
  - `parsers/focusTree.ts` extracts `Focus` objects from a `common/national_focus` file. Cost is in weeks, converted to days. Each `prerequisite = { ... }` block is an OR group, and multiple blocks are ANDed.
  - `parsers/localisation.ts` reads `.yml` names.
  - `gameImport.ts` ties these together, in phases: parse the tree, read the definitions its
    effects refer to, read the countries and events it mentions, load localisation, then put
    names and stat definitions onto the effect lines. Its helpers live in `gameFiles.ts` (the
    `GameFiles` interface of `readText`/`listFiles`, and `GAME_PATHS`), `definitions.ts`
    (`readDefinitions`, `readCountryHistory`) and `names.ts` (loading localised text).
  - `focusEffects.ts` is a barrel over `src/domain/effects/`, whose header documents the whole
    effect pipeline in the order it runs. Inside: `lines.ts` (flattening, plus `opensBlock` /
    `blockEnd` / `childrenOf` / `outdent`, which every pass uses instead of hand-rolled index
    arithmetic), `collapse.ts`, `passes.ts`, `conditions.ts`, `format.ts`, `ideaLines.ts` and
    `statKeys.ts`.
- `src/import/` holds the browser-only pieces: `gameFolder.ts` implements `GameFiles` using `showDirectoryPicker` (Chromium, reads lazily) or `<input webkitdirectory>` (other browsers, which list every file in the install), and `cache.ts` is the IndexedDB cache.
- Hovering a card shows a tooltip (`FocusTreeGraph.vue`) with the description (`<id>_desc` localisation), prerequisites and the flattened `completion_reward` (`Focus.effects`). Reward values such as idea ids are resolved to names via localisation. Effects are shown as humanized script lines, not translated to in-game wording, and each added idea's `modifier` block is inserted beneath its `add_ideas` line. `parsers/ideas.ts` reads those blocks: the country's `ideasFile` (see `countries.ts`) first, then other `common/ideas` files only for ids still missing (a plain `includes` check skips files before parsing). Stats go through one pipeline in `stats.ts`: a `StatDefinition` (label, kind percent/number/flag, decimals, goodWhen) is resolved at import from, in priority order, hand-written overrides in `src/data/statOverrides.ts` (extend this when a stat displays wrong), the game's `documentation/modifiers_documentation.md` (decimals and booleans only; it does not say percent vs number), then a guess (`_factor` keys and fractional values are percent). Labels come from `MODIFIER_<KEY>` or `modifier_<key>` localisation, falling back to the humanized key; building construction speeds (`production_speed_<building>_factor`) are title-cased (`Nuclear Reactor Construction Speed: +25%`) and always good when positive. A `46 = { ... }` block is a state scope, named from `STATE_46` localisation. `collapseEffects` (in `effects/collapse.ts`) folds `add_popularity = { ideology popularity }` into one stat line with a `subject`, so it reads `Communist popularity: +10%`. `add_opinion_modifier = { target modifier }` is collapsed the same way, with its `value` and duration read from `common/opinion_modifiers` (`parsers/opinionModifiers.ts`) and shown as `Opinion of Soviet Union: +40 (A Deal with the Devil)` (coloured by sign, with the duration after the modifier name when there is one); `SOV = { ... }` scope headers show the country name too. Country names follow the ruling party at game start, read from `history/countries/<TAG> - *.txt` (`SOV_communism` is "Soviet Union", while plain `SOV` is "Russia"). Every path the importer reads is listed once, in `GAME_PATHS` in `gameFiles.ts`; the non-Chromium folder fallback derives its filter from it (`READ_PATH_PREFIXES`), so add a directory there and it is readable in every browser. `readDefinitions` in `definitions.ts` is the shared "find ids in a directory of definition files" helper (preferred file first, `includes` check before parsing), and `findBlocks` in `parsers/paradoxScript.ts` does the layout-independent lookup. Collapsing is table-driven (`COLLAPSERS` in `effects/collapse.ts`: header key to a function building the one-line replacement), so add a compound effect there — most are the same shape and are built by the `aboutSubject` or `namedBy` factories rather than written out; `diplomatic_relation` is collapsed to `Military access with Romania: yes`. `simplifyRandomStates` tidies `random_owned_controlled_state` (the `prioritize` state ids move onto the header as `preferStates`, named via `STATE_<id>` localisation, and the `limit` is always dropped, since it only says which states qualify (the `if` limits are handled by `foldConditions` instead)), and `add_resource` collapses to `Add production of 8 Oil` (name from `state_resource_<type>`). `add_relation_modifier` reads `Gains <name> when dealing with <country>`, with the modifier's stats (from the static modifiers in `common/modifiers`, via `parsers/staticModifiers.ts`; conditions like `valid_relation_trigger` and zero values are dropped) listed beneath. Simple effects: `key = number` stat effects (`STAT_EFFECT_KEYS`: stability, political power, research slots, army/air/navy experience) go through the stat pipeline, so their labels live in `statOverrides.ts`; `set_rule = { x = yes }` becomes a yes/no rule line; `set_country_flag`, `set_state_flag` and `clr_country_flag` are dropped (and a `hidden_effect` left empty by that), since the game shows nothing for them; `add_extra_state_shared_building_slots` is one of those stat effects (`Building slots: +1`); `add_tech_bonus` reads `2x 100% research bonus for: Industry` (same shape as the doctrine cost reduction) (several `category`/`technology` fields, `ahead_reduction` shown as ignored ahead-of-time penalty), `add_mastery_bonus` reads `Doctrine mastery: +20% for 240 days on <track>`, and `set_technology` reads `Unlocks technology: <name>` (all three carried in `EffectLine.research`, names from localisation; a `$key$` name is a reference to another key); `add_building_construction` reads `Build 1 Military Factory (instantly)`; `create_equipment_variant` reads `Create design: <name>` (modules not shown); politics and leaders: `set_politics` reads `Ruling party: Non-Aligned (no elections)`, `set_political_party` `Set Non-Aligned popularity: 65%`, `set_party_name` `Rename Fascist party: <name>`, `promote_character` `Promote <name> to country leader (<ideology>)`, `create_country_leader` `<name> Becomes Leader` with each of its `traits` listed beneath as `Leader trait: Hedonist` and that trait's stats under it (`add_country_leader_trait` lists them the same way; read from `common/country_leader` by `parsers/leaderTraits.ts`, which shares `parseStatBlocks` with `parsers/staticModifiers.ts`; only plain non-zero numbers; corps commander traits are not read), and stat tones default by key in `defaultGoodWhen` (`*_cost_factor` better lower, building construction speeds better higher) before `statOverrides.ts`, (its sub-ideology such as `despotism` is an empty label in `common/ideologies`, so it is not shown), `create_corps_commander` `Create corps commander: <name>`, `set_autonomy` `Autonomy of Romania: Personal Union`, DLC branches: `has_dlc = X` and `NOT = { has_dlc = X }` in an `if` limit are resolved by `resolveDlcConditions` for the DLCs listed in `src/data/dlc.ts` (`ownedDlc`, passed to `importCountryFocuses`; the player owns Man the Guns, By Blood Alone and Death or Dishonor), with or without an `else` (inside the `if` or following it): the branch that applies replaces the `if`, and when the limit has other terms only the DLC term is removed (or the whole `if` when it fails); **the player does not own Arms Against Tyranny yet, so MIO rewards show their `else` branch (a designer idea), and this is expected to change**: flip the flag in `dlc.ts` (MIO effects such as `mio:<id> = { add_mio_funds }` are not formatted yet, so that branch needs display work first). `division_template` blocks are dropped (`DROPPED_BLOCKS`; the focus's tooltip already describes the unit), `create_unit` reads `Create unit: <template name>` (the name is pulled out of its escaped-quote `division` string), and `pruneEmptyBlocks` removes `if`/`else`/`hidden_effect`/random-state blocks left with no effect (a `limit` is not an effect). `foldConditions` (run after names are resolved) folds a `limit` into the header it belongs to (`if`, `else_if`, `every_other_country`) as a `condition`: `If France is in faction with: Britain:`, `NOT`/`OR`/`AND` written out (`not (...)`, `(a or b)`), scopes as `Yugoslavia (has war: yes or is subject: yes)`, blocks of fields as `has country leader (id: 550)`, comparisons keep their operator (`EffectLine.operator`, so `communism > party_popularity@fascism` reads `Communist popularity > Fascist popularity`); a limit holding anything else stays raw. An `if` with an empty limit (the game files comment the DLC check out) always applies, so it is dropped with its `else` branches and the body is shown; `else` reads `Otherwise:` and `else_if` `Otherwise, if ...:`. Script array effects (`remove_from_array`, `add_to_array`) and `log` are dropped as bookkeeping, and `pruneEmptyBlocks` also removes emptied country/`capital_scope` scopes, `unwrapEventConditions` drops the `if`/`limit` around events sent to other countries (only when the whole body is such events and there is no `else`), `create_faction_from_template` `Create faction: Cordon Sanitaire` (name key from the effect; template goals and rules not shown), plus one-word effects (`retire_country_leader`, leader traits, `retire_character`, `set_cosmetic_tag`, `add_claim_by`) through `LABELLED_EFFECTS` in `effects/format.ts`; `add_country_leader_role` reads `Becomes country leader` (with the leader's traits listed beneath like `create_country_leader`) under a character scope header (`ROM_ion_antonescu = { ... }` is shown by the character's localised name), `add_breakthrough_progress` reads `Nuclear Research breakthrough progress: +75%`, texts built from other texts (`$KEY$` references) are filled in after loading localisation, and an idea with a `name = X` field (shared text) is named from `X` (`parseIdeaNames`); `news_event` reads `News: <title>`; `remove_opinion_modifier`, `add_timed_idea` and the decision/idea tooltip effects have their own wording in `effects/format.ts`. `add_idea`, `add_timed_idea` and `show_ideas_tooltip` also list the idea's modifiers beneath, and `remove_ideas`/`remove_idea` list them reversed (`reverseModifier`: `+1.00%` becomes `-1.00%`, a `yes` rule becomes `no`), coloured by the reversed value. `create_wargoal` reads `Gain <wargoal type> wargoal on <country>` (the type's name is in `goals_l_english.yml`; the `generator` states are not shown). `country_event` (plain or block form; delays are dropped) reads `Event: <title>`: the title key comes from the event definition (`parsers/events.ts`, found by id in `events/`, trying the file named like the id prefix first), and `From`/`Root` in the raw localisation text (kept via `parseLocalisation`'s `raw` map) are filled in by `resolveEventText`, with the faction name taken from the receiving country's `create_faction_from_template` in its history file (falling back to "our faction"). `custom_effect_tooltip = KEY` shows the localised text as is, and everything inside `hidden_effect` is marked `hidden` (`markHidden`) and drawn grey and italic under a `Hidden effect:` header. `formatEffect`/`effectTone` (`effects/format.ts`) render lines: wording is dispatched on the effect name through the `FORMATTERS` table, and a formatter that returns null falls through to the generic `<key>: <value>` wording, so a partly understood effect still reads sensibly. `EffectList.vue` draws the result for both the tooltip and the plan, and the UI colours good/bad changes. An idea's `modifier` block and its `rule` block (yes/no game rules like `can_send_volunteers`, shown as flags: `Can send volunteers: yes`, green for yes and red for no unless `goodWhen: 'negative'`) are read, not `targeted_modifier` and similar. `cleanLocalisation` strips colour codes and turns `[SCOPE.GetName]` into the scope tag.
- `src/domain/plan/focusPlan.ts` has `schedulePlan`, which schedules an ordered list of focus ids back to back, at `days / (1 + speedBonus)` each. It reports prerequisite, exclusivity and duplicate problems per focus, and still schedules invalid focuses.
- `src/domain/plan/focusSelection.ts` drives selection: `pathTo` returns the focuses to append so a clicked focus becomes valid (missing prerequisites first, cheapest option for OR groups, null if blocked by exclusivity). `removeWithDependents` drops a focus plus anything that loses its prerequisites. `isValidPlan` gates reordering. The UI therefore keeps the plan valid at all times, while `schedulePlan` still reports rule violations as a safety net.
- `src/domain/plan/focusLayout.ts` resolves each focus's `x`/`y` (relative to `relative_position_id` when set) into absolute grid positions. `FocusTreeGraph.vue` draws the tree from them: absolutely positioned cards over an SVG of connector lines (px-per-grid-unit constants are at its top). Clicking a card toggles it in the plan; blocked cards are disabled. Game icons are deliberately not shown (copyrighted DDS art).
- The IndexedDB cache is versioned (`CACHE_VERSION` in `cache.ts`). Bump it when the `Focus` shape changes, which makes users re-import.
- `src/data/countries.ts` is the country selector list (only Romania so far). Each entry names its focus tree file.
- **Starting state:** `parsers/countryStart.ts` reads the 1936 part of `history/countries/<TAG> - *.txt` (starting `add_ideas`, `set_stability`/`set_war_support`/`set_research_slots`, `set_politics`, `set_popularities`; not techs, characters, OOBs or dated `1939.1.1` blocks) as effect lines, with stats turned into the additive keys (`add_stability`, ...) and popularities into `add_popularity` fractions. A top-level `if = { limit = { has_dlc = X } }` follows `ownedDlc` (unlisted DLCs count as not owned, so the Death or Dishonor king idea is absent until it is added to `dlc.ts`). `importCountryFocuses` returns `{ focuses, start }` (`ImportedCountry`); the start lines ride through the same name/modifier/stat passes as a pseudo focus `__start__` and are cached with the focuses. `ImportTarget` needs the country `tag`. The starting leader is a `promote_character` line the importer adds (`parsers/leaders.ts`): the first `recruit_character` in the history whose `common/characters/<TAG>.txt` `country_leader` ideology belongs to the ruling party (sub-ideology to group via `common/ideologies`). `CountryState.leader` is `{ name, ideology, traits }` (traits listed beneath a `create_country_leader`/`add_country_leader_role` count as the leader's, not as one-off stat changes, and their stats are summed into the modifier totals); the overview shows it in its own Leader section.
- **`countryStateAt`** (`domain/campaign/countryState.ts`) applies the rewards of the focuses completed by a date. `foldConditions` records each `if`/`else_if` limit it can read as `EffectLine.check` (a `Check` in `focus.ts`: `has_idea`, `has_completed_focus`, `has_tech`, `has_government`, an ideology's popularity against another's or a fraction, `NOT`/`OR`/`AND`, and `unknown` for terms we cannot answer), and `resolveConditions` (`campaign/conditions.ts`) settles those against what the campaign knows when the focus completes (ideas active, focuses completed earlier in the plan, the ruling party set so far, popularity once the start has set it, and `hasTech`, which nothing answers until the research planner exists). Evaluation is three-valued (`evaluateCheck`: true, false or undefined; one decisive term settles an `all`/`any` beside an unknown one). The branch that applies replaces the whole chain (`else` nested in the `if` or `else_if`/`else` following it) and counts like any other lines, so focuses that remove whichever idea the player has, or pick the ruling party by popularity, work; a chain that cannot be settled stays from its first unanswered branch on (a leading `else_if` becomes an `if`) and is listed as conditional. Conditions are settled against the state before the focus's own effects, so a popularity change and an `if` on it in the same reward see the old value. `has_country_leader = { id = N }` / `{ character = X }` is answered from who leads (`identity` in `countryStateAt`: `create_country_leader` carries its `id` as `EffectLine.leaderId`, `promote_character` and `add_country_leader_role` give a character, and it is unknown again after `retire_country_leader`, since the game picks the next leader); a character never matches a legacy id, so in a 1936 start `id = 550` (Carol II, only created in the `1939.1.1` block) is false. The game picking a new leader is modelled from `ImportedCountry.leaders` (`LeaderData` in `focus.ts`: the recruited characters with a `country_leader` role, in order, as named `promote_character` lines grouped by ideology group, plus the sub-ideology to group map; read by `readLeaderSources`/`listLeaderCandidates` and carried through the name passes as a pseudo focus `__leaders__`, passed on as `options.leaders`): when a reward retires the leader, or changes the ruling party to one the leader (whose group is known from a `create_country_leader` or `promote_character` ideology) does not lead for, and does not make a leader itself, the leader becomes the first candidate of the ruling party who has not been retired. Not answered yet: other countries' state (factions, wars, their leaders), and `has_tech`. With `options.start`/`startDate` the start lines are applied first as a step with id `START_ID`, so stat totals and popularity are absolute (start plus plan). Top-level lines and those inside `hidden_effect` or the country's own scope count; `if`/`else`/`random_*`/`every_*` blocks are only listed (`conditional`), except that `add_resource` and `add_building_construction` are always collected (top-level ones, those inside a `random_owned_*state` block, which picks one of the country's own states, and those inside a numbered state scope `46 = { ... }`, which is assumed to be the country's own for now, so add an escape hatch if that turns out wrong). Resources and buildings are summed per type (`resources` "Resources added", `buildings` "Buildings added", instant builds counted apart), whatever state they go to; the rest of a random block stays conditional, and other countries' scopes, state scopes and other countries' characters are skipped. Ideas are added, removed or (for `add_timed_idea`) expire, and their modifiers are summed. Starting ideas and stats from `history/countries` are not included yet.
- `src/stores/campaign.ts` (`useCampaign()`) is the one shared campaign: country, imported focuses, plan, start date, speed bonus, the overview's `viewDate`, and import status. It is a module-level singleton, so every page shares it. The plan and settings are saved to localStorage (`hoi4-companion:campaign`); focuses stay in the IndexedDB cache. A saved plan is kept when the focuses load and still valid, and cleared when the country changes.
- Routes (`src/router/index.ts`, hash history so reloads work on GitHub Pages): `/` is `views/OverviewView.vue` (date scrubber, government, national spirits, summed modifiers; `components/overview/`) and `/focus` is `views/FocusPlanView.vue` wrapping `components/focus/FocusPlanner.vue` (the plan: a list grouped under completion-year banners, showing each focus's dates and completion effects; focuses are added and removed only through the graph). `App.vue` has the header, country selector and nav, and keeps pages alive (`KeepAlive`) so switching keeps scroll and state; each view needs a single root element for that. A plan row's end date opens the overview on that date (`completionDay`). `components/GameDataImport.vue` is the folder picker.
- The `@` alias points to `src/`.
