# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Hearts of Iron IV companion web app for planning campaigns, starting with a national focus tree planner (production, divisions, navy, etc. may come later). It is a client-side Vue 3 + TypeScript + Vite single-page app with no backend.

## Commands

- `npm run dev`: start the Vite dev server (the app is served under `/hoi4-companion/`)
- `npm run build`: run `vue-tsc` type-check and `vite build` in parallel, writing to `dist/`
- `npm run test`: run Vitest once (`npx vitest run src/domain/__tests__/focusPlan.test.ts -t "name"` for a single file or test)
- `npm run type-check`: type-check only (`vue-tsc --build`)
- `npm run lint`: ESLint with `--fix` (flat config in `eslint.config.ts`)
- `npm run format`: Prettier on `src/` (no semicolons, single quotes, print width 100)

Tests live in `__tests__/` folders, which `tsconfig.app.json` excludes from type-checking.

## Deployment

Every push triggers `.github/workflows/main.yml`, which runs `npm install` and `npm run build`. Pushes to `main` also deploy `dist/` to GitHub Pages. That is why `vite.config.ts` sets `base: '/hoi4-companion/'`. Keep that base path when changing routing or asset URLs.

## Architecture

**No game data is committed or hosted.** The app reads focus trees from the user's own Hearts of Iron IV install, in their browser, and caches the parsed result in IndexedDB. Never add extracted game files or data to the repo. `HOI4_DIR="/path/to/Hearts of Iron IV" npm run test` also runs a test against a real install (skipped otherwise).

- Game logic is plain TypeScript with no Vue or DOM imports, so it is testable in Node. Keep it in `src/domain/`. Components only render it.
- Import pipeline:
  - `paradoxScript.ts` is a generic parser for Paradox script. It keeps duplicate keys and order.
  - `focusTree.ts` extracts `Focus` objects from a `common/national_focus` file. Cost is in weeks, converted to days. Each `prerequisite = { ... }` block is an OR group, and multiple blocks are ANDed.
  - `localisation.ts` reads `.yml` names.
  - `gameImport.ts` ties these together behind a `GameFiles` interface (`readText`, `listFiles`).
- `src/import/` holds the browser-only pieces: `gameFolder.ts` implements `GameFiles` using `showDirectoryPicker` (Chromium, reads lazily) or `<input webkitdirectory>` (other browsers, which list every file in the install), and `cache.ts` is the IndexedDB cache.
- Hovering a card shows a tooltip (`FocusTreeGraph.vue`) with the description (`<id>_desc` localisation), prerequisites and the flattened `completion_reward` (`Focus.effects`). Reward values such as idea ids are resolved to names via localisation. Effects are shown as humanized script lines, not translated to in-game wording, and each added idea's `modifier` block is inserted beneath its `add_ideas` line. `ideas.ts` reads those blocks: the country's `ideasFile` (see `countries.ts`) first, then other `common/ideas` files only for ids still missing (a plain `includes` check skips files before parsing). Stats go through one pipeline in `stats.ts`: a `StatDefinition` (label, kind percent/number/flag, decimals, goodWhen) is resolved at import from, in priority order, hand-written overrides in `src/data/statOverrides.ts` (extend this when a stat displays wrong), the game's `documentation/modifiers_documentation.md` (decimals and booleans only; it does not say percent vs number), then a guess (`_factor` keys and fractional values are percent). Labels come from `MODIFIER_<KEY>` or `modifier_<key>` localisation, falling back to the humanized key; building construction speeds (`production_speed_<building>_factor`) are title-cased (`Nuclear Reactor Construction Speed: +25%`) and always good when positive. A `46 = { ... }` block is a state scope, named from `STATE_46` localisation. `collapseEffects` (in `focusEffects.ts`) folds `add_popularity = { ideology popularity }` into one stat line with a `subject`, so it reads `Communist popularity: +10%`. `add_opinion_modifier = { target modifier }` is collapsed the same way, with its `value` and duration read from `common/opinion_modifiers` (`opinionModifiers.ts`) and shown as `Opinion of Soviet Union: +40 (A Deal with the Devil)` (coloured by sign, with the duration after the modifier name when there is one); `SOV = { ... }` scope headers show the country name too. Country names follow the ruling party at game start, read from `history/countries/<TAG> - *.txt` (`SOV_communism` is "Soviet Union", while plain `SOV` is "Russia"). Every directory the importer reads must also be listed in `NEEDED_PREFIXES` in `gameFolder.ts`, or the non-Chromium folder fallback silently drops those files. `readDefinitions` in `gameImport.ts` is the shared "find ids in a directory of definition files" helper (preferred file first, `includes` check before parsing), and `findBlocks` in `paradoxScript.ts` does the layout-independent lookup. Collapsing is table-driven (`COLLAPSERS` in `focusEffects.ts`: header key to a function building the one-line replacement), so add a compound effect there; `diplomatic_relation` is collapsed to `Military access with Romania: yes`. `simplifyRandomStates` tidies `random_owned_controlled_state` (the `prioritize` state ids move onto the header as `preferStates`, named via `STATE_<id>` localisation, and the `limit` is always dropped, since it only says which states qualify (the `if` limits are handled by `foldConditions` instead)), and `add_resource` collapses to `Add production of 8 Oil` (name from `state_resource_<type>`). `add_relation_modifier` reads `Gains <name> when dealing with <country>`, with the modifier's stats (from the static modifiers in `common/modifiers`, via `staticModifiers.ts`; conditions like `valid_relation_trigger` and zero values are dropped) listed beneath. Simple effects: `key = number` stat effects (`STAT_EFFECT_KEYS`: stability, political power, research slots, army/air/navy experience) go through the stat pipeline, so their labels live in `statOverrides.ts`; `set_rule = { x = yes }` becomes a yes/no rule line; `set_country_flag`, `set_state_flag` and `clr_country_flag` are dropped (and a `hidden_effect` left empty by that), since the game shows nothing for them; `add_extra_state_shared_building_slots` is one of those stat effects (`Building slots: +1`); `add_tech_bonus` reads `2x 100% research bonus for: Industry` (same shape as the doctrine cost reduction) (several `category`/`technology` fields, `ahead_reduction` shown as ignored ahead-of-time penalty), `add_mastery_bonus` reads `Doctrine mastery: +20% for 240 days on <track>`, and `set_technology` reads `Unlocks technology: <name>` (all three carried in `EffectLine.research`, names from localisation; a `$key$` name is a reference to another key); `add_building_construction` reads `Build 1 Military Factory (instantly)`; `create_equipment_variant` reads `Create design: <name>` (modules not shown); politics and leaders: `set_politics` reads `Ruling party: Non-Aligned (no elections)`, `set_political_party` `Set Non-Aligned popularity: 65%`, `set_party_name` `Rename Fascist party: <name>`, `promote_character` `Promote <name> to country leader (<ideology>)`, `create_country_leader` `<name> Becomes Leader` (its sub-ideology such as `despotism` is an empty label in `common/ideologies`, so it is not shown), `create_corps_commander` `Create corps commander: <name>`, `set_autonomy` `Autonomy of Romania: Personal Union`, DLC branches: `if = { limit = { has_dlc = X } ... } else = { ... }` is resolved by `resolveDlcConditions` for the DLCs listed in `src/data/dlc.ts` (`ownedDlc`, passed to `importCountryFocuses`), keeping only the branch that applies; **the player does not own Arms Against Tyranny yet, so MIO rewards show their `else` branch (a designer idea), and this is expected to change**: flip the flag in `dlc.ts` (MIO effects such as `mio:<id> = { add_mio_funds }` are not formatted yet, so that branch needs display work first). `division_template` blocks are dropped (`DROPPED_BLOCKS`; the focus's tooltip already describes the unit), `create_unit` reads `Create unit: <template name>` (the name is pulled out of its escaped-quote `division` string), and `pruneEmptyBlocks` removes `if`/`else`/`hidden_effect`/random-state blocks left with no effect (a `limit` is not an effect). `foldConditions` (run after names are resolved) folds a `limit` into the header it belongs to (`if`, `else_if`, `every_other_country`) as a `condition`: `If France is in faction with: Britain:`, `NOT`/`OR`/`AND` written out (`not (...)`, `(a or b)`), scopes as `Yugoslavia (has war: yes or is subject: yes)`, blocks of fields as `has country leader (id: 550)`, comparisons keep their operator (`EffectLine.operator`, so `communism > party_popularity@fascism` reads `Communist popularity > Fascist popularity`); a limit holding anything else stays raw. An `if` with an empty limit (the game files comment the DLC check out) always applies, so it is dropped with its `else` branches and the body is shown; `else` reads `Otherwise:` and `else_if` `Otherwise, if ...:`. Script array effects (`remove_from_array`, `add_to_array`) and `log` are dropped as bookkeeping, and `pruneEmptyBlocks` also removes emptied country/`capital_scope` scopes, `unwrapEventConditions` drops the `if`/`limit` around events sent to other countries (only when the whole body is such events and there is no `else`), `create_faction_from_template` `Create faction: Cordon Sanitaire` (name key from the effect; template goals and rules not shown), plus one-word effects (`retire_country_leader`, leader traits, `retire_character`, `set_cosmetic_tag`, `add_claim_by`) through the labels table in `formatEffect`; `add_country_leader_role` is not collapsed yet; `news_event` reads `News: <title>`; `remove_opinion_modifier`, `add_timed_idea` and the decision/idea tooltip effects have their own wording in `formatEffect`. `add_idea`, `add_timed_idea` and `show_ideas_tooltip` also list the idea's modifiers beneath. `create_wargoal` reads `Gain <wargoal type> wargoal on <country>` (the type's name is in `goals_l_english.yml`; the `generator` states are not shown). `country_event` (plain or block form; delays are dropped) reads `Event: <title>`: the title key comes from the event definition (`events.ts`, found by id in `events/`, trying the file named like the id prefix first), and `From`/`Root` in the raw localisation text (kept via `parseLocalisation`'s `raw` map) are filled in by `resolveEventText`, with the faction name taken from the receiving country's `create_faction_from_template` in its history file (falling back to "our faction"). `custom_effect_tooltip = KEY` shows the localised text as is, and everything inside `hidden_effect` is marked `hidden` (`markHidden`) and drawn grey and italic under a `Hidden effect:` header. `formatEffect`/`effectTone` render lines, and the UI colours good/bad changes. An idea's `modifier` block and its `rule` block (yes/no game rules like `can_send_volunteers`, shown as flags: `Can send volunteers: yes`, green for yes and red for no unless `goodWhen: 'negative'`) are read, not `targeted_modifier` and similar. `cleanLocalisation` strips colour codes and turns `[SCOPE.GetName]` into the scope tag.
- `src/domain/focusPlan.ts` has `schedulePlan`, which schedules an ordered list of focus ids back to back, at `days / (1 + speedBonus)` each. It reports prerequisite, exclusivity and duplicate problems per focus, and still schedules invalid focuses.
- `src/domain/focusSelection.ts` drives selection: `pathTo` returns the focuses to append so a clicked focus becomes valid (missing prerequisites first, cheapest option for OR groups, null if blocked by exclusivity). `removeWithDependents` drops a focus plus anything that loses its prerequisites. `isValidPlan` gates reordering. The UI therefore keeps the plan valid at all times, while `schedulePlan` still reports rule violations as a safety net.
- `src/domain/focusLayout.ts` resolves each focus's `x`/`y` (relative to `relative_position_id` when set) into absolute grid positions. `FocusTreeGraph.vue` draws the tree from them: absolutely positioned cards over an SVG of connector lines (px-per-grid-unit constants are at its top). Clicking a card toggles it in the plan; blocked cards are disabled. Game icons are deliberately not shown (copyrighted DDS art).
- The IndexedDB cache is versioned (`CACHE_VERSION` in `cache.ts`). Bump it when the `Focus` shape changes, which makes users re-import.
- `src/data/countries.ts` is the country selector list (only Romania so far). Each entry names its focus tree file.
- `src/components/focus/FocusPlanner.vue` holds the country, plan (a list grouped under completion-year banners, showing each focus's dates and completion effects; focuses are added and removed only through the graph), start date and speed bonus, and wires up import and cache.
- The `@` alias points to `src/`. `src/router/index.ts` is set up but has no routes yet.
