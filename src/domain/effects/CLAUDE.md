# Effect pipeline and display (`src/domain/effects/`, `focusEffects.ts`)

  - `focusEffects.ts` is a barrel over `src/domain/effects/`, whose header documents the whole
    effect pipeline in the order it runs. Inside: `lines.ts` (flattening, plus `opensBlock` /
    `blockEnd` / `childrenOf` / `outdent`, which every pass uses instead of hand-rolled index
    arithmetic), `collapse.ts`, `passes.ts`, `conditions.ts`, `format.ts`, `ideaLines.ts` and
    `statKeys.ts`.
- **Effect display.** Hovering a card (`FocusTreeGraph.vue`) shows the description (`<id>_desc` localisation), prerequisites and the flattened `completion_reward` (`Focus.effects`); the plan shows the same lines. Both draw the reward as of its completion (`CountryState.focusEffects`), with the branches of `if`/`else` chains that do not apply dimmed and marked `(does not apply)` (`EffectList.vue`, from `EffectLine.branch`); a focus not in the plan shows a preview under `If added next` (with its missing prerequisites first), worked out only on hover by `previewFocusEffects` in `campaign/preview.ts` (it does not rerun the research or political power planning, so `hasTech` and the purchases are the current campaign's), and a focus blocked by exclusivity shows the raw lines. By default `EffectList.vue` leaves the skipped branches out entirely; the "Show branches that do not apply" checkbox on the focus page (`components/focu./effectDisplay.ts`, a shared ref kept in localStorage, off by default) draws them dimmed again. A "Show hidden effects" checkbox (`showHiddenEffects`, same file, on by default) drops every line marked `hidden` before the other two apply. The Simplify checkbox next to it (`simplifyEffects`, same file, off by default, overrides the other) runs the lines through `onlyWhatHappens` (`effects/onlyWhatHappens.ts`): skipped branches are dropped, the header of the branch that applies is dissolved with its lines lifted a level (at any depth), and blocks left empty go; a `swap_ideas` block becomes plain `add idea` / `remove idea` lines, or, when it removes and adds an idea of the same name, `Replace idea X with X:` over a `Net change:` line and the summed modifiers (`replace_idea` / `net_change` in `format.ts`); chains the campaign could not settle carry no marks and stay as written. `EffectList.vue` draws both and colours good/bad changes. Effects are humanized script lines, not translated to in-game wording, with reward values resolved to localised names. The pipeline is documented in the header of `focusEffects.ts`; the wording of each effect lives in `effects/format.ts` (`FORMATTERS`, dispatched on the effect name; a formatter that returns null falls through to the generic `<key>: <value>`) and `effects/collapse.ts` (`COLLAPSERS`: header key to a one-line replacement, mostly built by the `aboutSubject` / `namedBy` factories), and the tests show examples. To add a compound effect, add a collapser; for a one-word effect, `LABELLED_EFFECTS` in `format.ts`.
  - **Definitions read by id:** ideas (`parsers/ideas.ts`: the country's `ideasFile` first, then other `common/ideas` files only for ids still missing, with a plain `includes` check before parsing; only the `modifier` and `rule` blocks, not `targeted_modifier`), opinion modifiers, static modifiers (relation modifiers) and leader traits (`parsers/statBlocks.ts`: plain non-zero numbers only; corps commander traits are not read). Their stats are listed beneath the line that applies them (`effects/modifierLines.ts`), reversed for removals (`reverseModifier`). `readDefinitions` is the shared helper and `findBlocks` in `paradoxScript.ts` the layout-independent lookup.
  - **`custom_modifier_tooltip`** in an idea's `modifier` block is the game's own text for something it cannot show as a stat (a support company bonus): the line has no `stat`, `nameLines.ts` names it from the key's localisation, `format.ts` shows that text, and nothing sums it.
  - **Stats** go through one pipeline in `stats.ts`: a `StatDefinition` (label, kind percent/number/flag, decimals, goodWhen) resolved from, in priority order, `src/data/statOverrides.ts` (extend this when a stat displays wrong), the game's own tooltip text for the modifier (`<key>_tt`, or `modifier_<key>_tt`, asked for with every modifier line: `parseTooltipFormat` reads the value template, e.g. `$RIGHT|+=%1$`: the first letter is the colour (`+` positive is good, `-` negative is good, any other letter neutral, which clears a guessed direction), `%` percent, `%%` percent already in percentage points (`StatDefinition.percentPoints`, not multiplied by 100), no `%` a number, a digit the decimals; a rule stays a flag), the game's `documentation/modifiers_documentation.md` (decimals and booleans only, not percent vs number), then a guess (`_factor` keys and fractional values are percent). Labels come from the `<key>_tt` text first (it is what the game shows for that key, and tells `conscription` from `conscription_factor`, whose `MODIFIER_` names are swapped), then `MODIFIER_<KEY>` / `modifier_<key>` localisation, falling back to the humanized key. `defaultGoodWhen` sets the tone by key before the overrides (`*_cost_factor` better lower, building construction speeds better higher). Plain `key = number` effects (`STAT_EFFECT_KEYS`) also use this pipeline, so their labels live in `statOverrides.ts`.
  - **Left out on purpose:** `set_state_flag`, `add_ai_strategy`, the script variable effects (`set_variable`, `add_to_variable`, ... plain or in a block), array effects and `log`, `division_template` blocks (the focus tooltip already describes the unit), and any block left empty by that (`pruneEmptyBlocks`; a `limit` is not an effect). Everything inside `hidden_effect` is marked `hidden` and drawn grey and italic under a `Hidden effect:` header.
  - **Conditions:** `foldConditions` (run after names are resolved) folds a `limit` into the header it belongs to (`if`, `else_if`, `every_other_country`, and the state scopes `every_`/`random_` `core_state`, `controlled_state`, `owned_state`, `state`, which read `Every core state where ...:`; a `limit` that is not the first line of its block is moved there first, `limitFirst`) as an English `condition`, and records the readable ones as data in `EffectLine.check`; a limit holding anything else stays raw. An `if` with an empty limit (the game files comment the DLC check out) always applies, so its `else` branches are dropped and the body is shown.
  - **DLC branches:** `resolveDlcConditions` resolves `has_dlc` for the DLCs in `src/data/dlc.ts` (`ownedDlc`, hard-coded: every name the game files check is listed, so every `has_dlc` is settled; Together for Victory, Death or Dishonor, Waking the Tiger and Man the Guns are base game now and always on, the rest are the player's own, owned or not); the branch that applies replaces the `if`. **MIOs are base game** (since 1.14), so the political power planner always leaves out the tank/naval/aircraft/materiel designers (`MIO_SLOTS` in `politicsImport.ts`); the industrial and electronics concerns and the theorist stay. MIO effects such as `mio:<id> = { add_mio_funds }` are not formatted (they show as raw lines). **MIO import:** `parsers/mios.ts` (`readMios`) reads `common/military_industrial_organization/organizations` into `ImportedCountry.mios` (`MioData`, in `research.ts`): `include` copies the fields of another MIO (own fields win, an own `initial_trait` replaces the included one), `allowed` is checked for the tag and `ownedDlc` like a political option's (`isAllowed`; the `DEBUG_` copies are skipped; foreign MIOs a DLC lets the country license are kept, named `<TAG>_<id>` in localisation), `available` is a `Check` with `FROM = { ... }` read as its contents, `research_categories` are `mio_cat_tech_*` (which `Technology.categories` already holds) and the research bonus is `military_industrial_organization_research_bonus` of the `initial_trait`'s `organization_modifier`. The defines `DESIGN_TEAM_RESEARCH_BONUS` (`ResearchDefines.designTeamBonus`, 0.05) and `ASSIGN_DESIGN_TEAM_PP_COST_PER_DAY` (`PoliticsDefines.designTeamCost`, 0.1) are read by regex. Trait unlocks, policies, funds and size of a MIO are not modelled.
